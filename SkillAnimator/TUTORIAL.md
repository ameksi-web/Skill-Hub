# Как делать плагины для Roblox Studio — и как устроен Skill Animator

Этот файл — не реклама плагина, а разбор: что такое плагин технически, чем он
отличается от обычного скрипта, как его правильно собрать, упаковать и проверить,
и почему первая версия Skill Animator тихо ломала экспорт (и как это исправлено).
В конце — короткая инструкция по самому плагину.

> Всё, что ниже, проверено на этом репозитории: `tools/animator_test.py` поднимает
> плагин в мок-Studio и прогоняет **47 проверок**, включая математику экспорта.

---

## 1. Что такое плагин Roblox Studio

Плагин — это `Script`, который Studio запускает **в своём контексте**, а не в
игре. Отличия, которые определяют всё остальное:

| | Скрипт в игре | Плагин Studio |
|---|---|---|
| Где работает | клиент/сервер плейса | редактор Studio |
| Права | обычные | `PluginSecurity` (доступ к `Selection`, `ChangeHistoryService`, файлам) |
| Глобал `plugin` | нет | да — объект плагина |
| GUI | ScreenGui в PlayerGui | `plugin:CreateDockWidgetPluginGui` — **док** в интерфейсе Studio |
| Жизненный цикл | пока игра запущена | пока Studio открыта; перезагружается на каждом старте |
| Где лежит | внутри места | папка Plugins на диске или аккаунт Creator |

Ключевое: плагин **не является частью места**. Он не сохраняется в `.rbxl`,
не публикуется с игрой и не виден игрокам.

## 2. Три способа поставить локальный плагин

### 2.1. Файл `.lua` в папке Plugins

```
Windows: %LOCALAPPDATA%\Roblox\Plugins
macOS:   ~/Documents/Roblox/Plugins
```

Плюс: просто. Минус: работает только для одиночного `Script`; положить рядом
`ModuleScript` нельзя — в `.lua` нет структуры дерева.

### 2.2. Файл `.rbxmx` (модель) в папке Plugins

Это правильный формат, если внутри больше одного объекта: скрипт + модули +
иконки. Studio на старте читает модели из папки и **запускает все включённые
`Script` внутри**. Именно так собирается `SkillAnimator/SkillAnimator.rbxmx`:

```xml
<roblox version="4">
  <Item class="Script" referent="RBX0">
    <Properties>
      <string name="Name">SkillAnimator</string>
      <bool name="Disabled">false</bool>
      <ProtectedString name="Source"><![CDATA[ -- код плагина ]]></ProtectedString>
    </Properties>
  </Item>
</roblox>
```

Тонкости, на которых ломаются чаще всего:

* файл должен лежать **прямо** в папке Plugins — вложенные `.rbxmx` Studio при
  старте не подхватывает;
* расширение именно `.rbxmx` (XML) или `.rbxm` (бинарный), а не `.lua.txt`;
* в `Source` нельзя встретить `]]>` — это закроет CDATA раньше времени.
  Генератор в этом репозитории экранирует такой случай и заодно вырезает
  управляющие символы, недопустимые в XML 1.0;
* `Disabled` должен быть `false`, иначе скрипт не выполнится.

### 2.3. «Save as Local Plugin…» из самого Studio

Правый клик по `Script` в Explorer → **Save as Local Plugin…** → Studio сама
положит `.rbxmx` в папку Plugins. Удобно, когда плагин пишется прямо в Studio.
Важно: сохранять нужно **скрипт (или модель-контейнер)**, а не `ModuleScript`
внутри места.

> Обновление: после замены файла плагин перезапускается только при следующем
> старте Studio. Если нужно быстрее — удалите и снова сохраните плагин из места,
> Studio подхватит сразу.

## 3. Анатомия плагина: минимальный рабочий пример

```lua
-- 1) точка входа — глобал plugin; в Command Bar его нет
if not plugin then
    error("этот файл запускается только как плагин Studio")
end

-- 2) панель инструментов
local toolbar = plugin:CreateToolbar("My Plugin")
local button = toolbar:CreateButton(
    "My Plugin",          -- подпись
    "Что делает кнопка",  -- подсказка
    "rbxassetid://123"    -- иконка (необязательно)
)

-- 3) док-панель
local info = DockWidgetPluginGuiInfo.new(
    Enum.InitialDockState.Bottom, -- где пристыковать
    false,                        -- Enabled при старте
    false,                        -- не восстанавливать прошлое состояние
    600, 300,                     -- размер по умолчанию
    400, 200                      -- минимальный размер
)
local widget = plugin:CreateDockWidgetPluginGui("MyPluginDock", info)
widget.Title = "My Plugin"

-- 4) содержимое
local frame = Instance.new("Frame")
frame.Size = UDim2.new(1, 0, 1, 0)
frame.BackgroundColor3 = Color3.fromRGB(20, 21, 27)
frame.BorderSizePixel = 0
frame.Parent = widget

-- 5) кнопка открывает/закрывает панель
button.Click:Connect(function()
    widget.Enabled = not widget.Enabled
    button:SetActive(widget.Enabled)
end)

-- 6) уборка при выгрузке плагина
plugin.Unloading:Connect(function()
    -- отключить соединения, уничтожить свои объекты в CoreGui
end)
```

Что здесь важно и почему:

* **`plugin` может быть `nil`.** Тот же файл, вставленный в Command Bar, упадёт
  на первой строке. Для отладки полезно иметь ветку `else` — Skill Animator
  в этом случае рисует временную панель в `CoreGui`.
* **`SetActive`** — не украшение: без него кнопка не подсвечивается, и
  пользователь не понимает, открыта панель или нет.
* **`DockWidgetPluginGuiInfo`** задаёт минимальный размер. Если содержимое
  больше минимума — при уменьшении дока кнопки и слайдеры будут обрезаны.
  Поэтому в Skill Animator обе строки кнопок — горизонтальные `ScrollingFrame`,
  а список слайдеров — вертикальный.

## 4. Что отличает «работает у меня» от «сделано нормально»

### 4.1. Жизненный цикл: всё, что живёт дольше панели, надо убивать

Самая частая утечка в плагинах — `RunService.RenderStepped:Connect`, который
продолжает работать после закрытия панели. Через несколько перезапусков в
одной сессии Studio таких циклов становится пять, и редактор начинает тормозить.

Правило: **каждое соединение складывать в список и рвать его при закрытии или
`plugin.Unloading`.**

```lua
local connections = {}
local function keep(connection)
    table.insert(connections, connection)
    return connection
end

keep(RunService.RenderStepped:Connect(function(dt) ... end))

plugin.Unloading:Connect(function()
    for _, connection in ipairs(connections) do
        pcall(function() connection:Disconnect() end)
    end
    connections = {}
end)
```

Skill Animator делает именно это (`Animator:DisconnectAll`) и проверяет результат
в тесте: после `Unloading` соединение playback-цикла `nil`.

### 4.2. Undo: один waypoint на действие, а не на пиксель

`ChangeHistoryService:SetWaypoint(name)` создаёт точку отмены. Если вызывать её
в `MouseDrag`, то одно движение мышью даст сотню точек, и Ctrl+Z перестанет
работать осмысленно.

Решение — батчи:

```lua
local depth = 0
local function beginBatch() depth += 1 end
local function endBatch()
    depth -= 1
    if depth == 0 then
        pcall(function()
            ChangeHistoryService:SetWaypoint("[My Plugin] edit")
        end)
    end
end
```

В Skill Animator так обёрнуты dragging gizmo и слайдеры.

### 4.3. Не создавать GUI заново

`plugin:CreateDockWidgetPluginGui("SameId", info)` с одинаковым Id возвращает
**ту же** панель. Если при каждом клике вызывать `BuildUI` заново, содержимое
задвоится. Правильно: построить один раз, а дальше менять свойства.

### 4.4. Selection — не только «что выделено»

`Selection:Get()` — массив. Он может содержать и `Model`, и `BasePart`, и
`KeyframeSequence`. Плагин должен уметь разбирать все варианты, а не падать на
первом неожиданном. В Skill Animator выбор части рига автоматически
переключает активный сустав (если включён `Follow`).

### 4.5. Ошибки не должны убивать плагин

Studio показывает ошибку в Output, но плагин после этого может остаться в
непонятном состоянии. Всё, что трогает чужие объекты (cвойства моторов,
`SetAttribute`, `SetWaypoint`), оборачивается в `pcall`, а пользователю
показывается строка статуса, а не стектрейс.

### 4.6. Производительность

Панель — это GUI, который перерисовывается. Не надо пересобирать дерево
джойнтов на каждую запись ключа: Skill Animator перерисовывает только нужную
дорожку (`refreshLane`), полный rebuild — только при смене рига/зума.

## 5. Сборка `.rbxmx` из исходника

В репозитории есть генератор:

```
python3 tools/build_plugin_rbxmx.py
# → SkillAnimator/SkillAnimator.rbxmx
```

Он делает ровно то, что описано в §2.2, и **сам себя проверяет**:

1. читает `SkillAnimator/init.lua`;
2. вырезает управляющие символы, запрещённые в XML;
3. экранирует `]]>` в CDATA;
4. пишет `<Item class="Script">` c `Disabled=false`;
5. парсит готовый файл обратно и сравнивает `Source` с исходником
   **посимвольно**;
6. проверяет, что код заканчивается на `return Animator`.

Если шаг 5 не сошёлся — сборка падает. Это защита от «файл записался, но
Studio его не прочитает».

## 6. Как тестировать плагин без Studio

В Studio нельзя запустить 47 сценариев за секунду, а руками проверять экспорт
анимации больно. Поэтому в репозитории есть мок Studio:
`tools/animator_test.py`.

Что он поднимает:

* виртуальные часы и планировщик `task.spawn/wait/delay` — циклы реально тикают;
* метатаблицу инстансов с `__namecall`, `IsA`, `FindFirstChild`, `Destroy`,
  `GetDescendants`, свойствами и сигнатурами;
* сервисы `Selection`, `ChangeHistoryService`, `TweenService`, `RunService`,
  `UserInputService`, `CoreGui`, `Workspace`;
* объект `plugin` с `CreateToolbar`, `CreateButton`,
  `CreateDockWidgetPluginGui` и `Unloading`;
* **настоящую CFrame-математику**: матрица 3×3 + позиция, `Inverse`,
  `ToEulerAnglesXYZ`, умножение кадр×кадр и кадр×вектор.

Последний пункт — главный. Плагин переводит градусы в `CFrame` и обратно; если
проверять его «фейковым» CFrame, который всегда возвращает себя, то сломанный
экспорт пройдёт тест.

Что конкретно проверяется (47 проверок):

* регистрация тулбара и дока, наличие кнопок, компоновка строк (ширина ≤ 980);
* авто-привязка рига из `Selection`;
* найдены все `Motor6D`, корень определён как «часть, которая никогда не Part1»;
* запись ключей, интерполяция на середине (45° из 0° и 90° при Linear),
  и то, что `Motor6D.C0` действительно изменился;
* экспорт: количество `Keyframe`, время = кадр / FPS, **иерархия `Pose`** —
  `Pose.Name == Part1`, `Pose.Parent.Name == Part0`;
* угол в экспортированном `Pose` равен записанному (с точностью 0.2°);
* easing попал в `Pose.EasingStyle`;
* импорт обратно совпадает по кадрам и углам;
* смена FPS пересчитывает время;
* зум меняет масштаб времени;
* duplicate/delete/навигация по ключам;
* выбор части рига переключает сустав;
* save/load проекта через атрибут рига;
* undo-waypoints пишутся;
* `plugin.Unloading` рвёт playback-цикл и гасит док;
* за всю сессию **ни одной ошибки и ни одного warn**.

Чего мок **не** видит: внешний вид (цвета, шрифты, реальные размеры шрифтов),
работу `Handles`/`ArcHandles` мышью, настоящую публикацию анимации. Это надо
проверять глазами в Studio.

## 7. Публикация плагина (если нужно)

1. Проверить, что плагин не зависит от места: не читает `workspace` конкретной
   игры, не ждёт `PlayerGui`.
2. В Studio: правый клик по контейнеру → **Save as Local Plugin** для локальной
   версии, либо **Plugins → Publish Plugin** для публикации в аккаунт.
3. Публичный плагин проходит модерацию; обновления — той же кнопкой (версия
   поднимается автоматически).
4. Не хранить в плагине ключи/токены: исходник плагина читается любым, у кого
   он установлен (`PluginDebugService`).

## 8. Частые ошибки (по опыту этого репозитория)

1. **`.rbxmx` в подпапке** — не грузится при старте Studio.
2. **`SkillAnimator.lua.txt`** — Windows дописал `.txt`, плагин не появился.
3. **Studio не перезапущена** — папка Plugins читается на старте.
4. **Скрипт лежит в месте, а не в плагине** — в Output пусто, кнопки нет.
5. **`plugin` в Command Bar** — `nil`, нужно ветку `else`.
6. **Колонка `plugin:CreateDockWidgetPluginGui` с новым Id при каждом клике** —
   плодятся панели.
7. **`RenderStepped` без `Disconnect`** — утечка циклов после закрытия дока.
8. **`SetWaypoint` в `MouseDrag`** — мусорная история Undo.
9. **`Motor6D.C0 = CFrame.Angles(...)` вместо `BaseC0 * delta`** — риг
   «прыгает»: теряется исходная поза сустава.
10. **Плоский экспорт `Pose`** (все под одним корнем) — анимация играется
    частично или не играется. Roblox матчит позы по именам: `Pose.Name` — это
    `Part1`, родительская `Pose` — `Part0`.
11. **`Animator:StatusLabel`** вместо `Animator.StatusLabel` — двоеточие в Lua
    означает вызов метода, и код не компилируется.
12. **`track` как имя функции и локальной переменной** — затенение, вызов
    таблицы. Именно на этом упала первая сборка v2.

## 9. Skill Animator v2: что внутри

* **Правильный экспорт.** Дерево `Pose` строится по графу `Motor6D`:
  `Part0 → Part1`, корень определяется автоматически (`HumanoidRootPart`,
  `Torso`, `PrimaryPart` как запасные варианты).
* **Импорт.** `KeyframeSequence` из `AnimSaves` (свой или из Animation Editor)
  читается обратно в таймлайн: кадр = `Time × FPS`, поза = `CFrame`.
* **Проект на риге.** Save/Load пишут компактную строку в атрибут
  `SkillAnimatorProject`; переживает перезапуск Studio.
* **Таймлайн.** Зум (1×/2×/4×/8×), линейка с автоматическим шагом, скраб мышью,
  ромбы-ключи, навигация ◀ ▶, дублирование, удаление, копирование позы.
* **Инспектор.** RX/RY/RZ (−180…180), PX/PY/PZ (±4), слайдеры, FPS, длина,
  имя анимации, сброс сустава.
* **Undo.** Один waypoint на действие (drag и слайдеры — батчем).
* **Уборка.** Закрытие дока и `plugin.Unloading` гасят циклы и гизмо.

Ограничения, честно:

* только `Motor6D` (не поддерживает `Bone`/`Attachment`-риги и IK);
* имена частей должны быть уникальными (Roblox матчит позы по имени);
* нет onion skin, нескольких ригов одновременно и физического превью;
* атрибут проекта — текст, для гигантских анимаций (десятки тысяч ключей)
  он может упереться в лимит размера атрибута; тогда используйте Export →
  AnimSaves как основной формат.

## 10. Как пользоваться плагином

1. **Plugins → Plugins Folder** → положить `SkillAnimator.rbxmx` → перезапустить
   Studio. (Или: Explorer → правый клик по `Workspace` → **Insert from File…** →
   выбрать `.rbxmx` → правый клик по появившемуся скрипту → **Save as Local
   Plugin…**.)
2. Вкладка **Plugins → Skill Animator** → открыть панель.
3. Выделить риг (R6/R15/кастомный с `Motor6D`) → **Bind selected rig**.
   Если в месте ровно один риг, он подхватится сам.
4. Поставить кадр на линейке → выбрать сустав в списке → двигать кольцами
   `ArcHandles` (поворот) или стрелками (смещение), либо слайдерами справа.
   При `AutoKey` ключ ставится сам, кнопкой **◆ Add key** — вручную.
5. **Export → AnimSaves** — в риге появится `AnimSaves/SkillAnimation_01`
   (`KeyframeSequence`). Это нативный формат: его можно открыть в Animation
   Editor и опубликовать как обычную анимацию.
6. **Import from AnimSaves** — вернуть существующую анимацию в таймлайн
   (выделите `KeyframeSequence` в Explorer перед нажатием, либо плагин возьмёт
   ту, что совпадает с текущим именем).
7. **Save project / Load project** — сохранить работу на самом риге.
8. FPS и число кадров меняются в инспекторе (поля `FPS` / `Frames`); имя
   анимации — поле `Animation name`.

Проверка результата: откройте `AnimSaves`, выделите `KeyframeSequence`, и в
Explorer раскройте `Keyframe → Pose`. У правильной анимации `Pose` вложены
цепочкой: `HumanoidRootPart → Torso → Head/Left Arm/…`, а имя каждой `Pose`
совпадает с именем части.
