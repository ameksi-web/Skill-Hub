Three products live in this repository: the locked Blox Fruits build, the Skill
Animator Studio plugin, and a family of free keyless game hubs (Slayers 2,
Jujutsu Shenanigans, Steal An Egg, RIVALS):

### RIVALS — what is in this build (2026-10-17)

Nine tabs: **Combat · Trigger · ESP · Weapons · Movement · Utility · Anti-Cheat ·
Fun · Player & Misc**, 73 switches, 40 self-checks inside the hub and 130 checks
in the harness below.

RIVALS resolves every shot on the server, so the combat tab is an input layer,
not a damage layer: it picks a target (team + visibility + crosshair priority,
with a 400-pixel penalty for anything behind cover), rotates the camera or moves
the mouse toward the chosen part, and stops at `AimStepLimit` degrees per frame.
The picker only considers targets inside the `AimFov` cone (degrees either side
of the crosshair) and holds the current target until another is 25 % better, so
the camera does not flicker between two neighbours.
Prediction leads by a fraction of the target's velocity, humanise jitters the
step, and the triggerbot clicks when a target crosses the crosshair. Fire
cadence is capped twice — by `FireRateCap` and by the anti-cheat shot ceiling —
and humanised cadence drops about one shot in twenty-five.

**Aim in a real match (v1.2).** The first build aimed in the lobby and went
quiet the moment a duel loaded. Three separate causes, all fixed:

* RIVALS replaces `workspace.CurrentCamera` when the arena finishes loading. The
  hub had captured the camera once at load and kept rotating the dead one; every
  read now goes through a live getter, and the harness swaps the camera under it
  to prove the aim follows.
* a match hands out a new character, and the ray filter, the movement write
  cache and the visibility state still described the old body — movement never
  re-applied and the picker could not trust its own eyes. `CharacterAdded` (plus
  a 20 ms poll) rebinds all of it; teams and records are re-read the moment a
  match is detected.
* the picker had no cone: "closest to crosshair" could choose someone behind
  you, and in a full match the camera spun instead of aiming. `AimFov` is now a
  real cone, the FOV ring is drawn from the same number (projected through the
  camera's field of view instead of a made-up pixel scale), and the 25 %
  hysteresis keeps the target from flickering.
* **writing `Camera.CFrame` alone is not enough.** RIVALS' camera controller
  recomputes the view from its own yaw/pitch every frame, so a CFrame-only aim
  bot shows the rotation for exactly one frame and then loses it — it looks like
  the aim works in the lobby and dies in a match. **Hybrid** (the default since
  v1.1) feeds the game's own mouse (`mousemoverel`) so the controller keeps the
  rotation it was given, and only writes the camera when the cursor is not
  driving the view.
* **a screen offset is not a mouse offset.** The v1.0 hybrid sent the number of
  pixels between the crosshair and the target; at 0.35°/px that is a 30–100°
  swing for a target a few degrees off-centre, so the camera crossed the target,
  dropped it out of the cone and snapped back. The step is now computed in
  degrees (yaw/pitch from the camera look vector, capped by `AimStepLimit`),
  converted through `AimMouseSensitivity` (slider in Combat), and the rotation
  the game actually applied is measured back from the camera after every move —
  an unusual in-game sensitivity is learned instead of guessed.
* if three moves in a row do not turn the view (unlocked cursor, menu, a
  Scriptable camera) Hybrid falls back to the CFrame path and retries the mouse
  1.5 s later. The Diagnostics dump shows the live path, the learned °/px and
  the number of fallbacks, so "aim does nothing" is answerable instead of
  guessable.

Every worker now runs its frame under `pcall`, so one bad frame cannot kill the
aim for the rest of the match; aim stops while dead instead of dragging the
spectate camera; and the Combat tab has three presets — *Duel · 1v1*,
*Match · 2v2 and casual*, *Close range* — which move the sliders and the config
together.

**Teardown and pacing (v1.3).** A second pass over the switches that are easy
to leave half-wired: panic now runs each switch's *off* callback, so low gravity
is actually restored (196.2) instead of staying at 80; the camera FOV control
defaults to **0 = leave the game's own FOV alone** and hands the original value
back when turned off, instead of forcing 100 every tick and fighting scopes;
auto scope is edge-triggered (one right-button press, one release) rather than
fifty presses a second; chat spam honours `ChatDelay` (15 s default) instead of
the loop tick; and with the speed hack off the hub no longer pins `WalkSpeed` to
16 every tick, so the game's own speed modifiers survive.

**Tabs and boot (v1.2).** The window, the tabs and every background worker are
now thirteen independent boot steps: a failing subsystem prints its own name and
the rest still come up, and if the window or the tabs cannot be built at all, a
compact safe-mode panel appears with the essentials (aim, trigger, ESP, chams,
speed, fly, no-recoil, report filter) instead of a silent `print`. **Diagnostics**
in *Player & Misc* dumps build, executor hooks, window, tab count, render driver,
per-worker heartbeats, camera, players, remotes, shots, aim method and the error
log. The harness no longer trusts the API alone for this: it finds the rail
buttons in the built ScreenGui and *clicks* all nine, clicks a toggle and checks
the config flipped, opens the Method dropdown and picks «Camera», presses a
preset's RUN button and checks the sliders moved, then fires `E` through
`UserInputService` and checks that aim toggled and the switch followed, and
finishes by arming the keybind widget and pressing `Q` to prove the rebind
writes the config, typing in the search box to prove the rail filters and comes
back, and pressing minimise, close and the hide key to prove the window can be
collapsed and recovered. The rebind widget now ignores keystrokes the game
already consumed, and the close button *hides* the window instead of disabling
its ScreenGui — disabling it left the script running but unreachable.

The **silent** method is conditional and labelled that way: it rewrites a CFrame
or unit-Vector3 direction argument on the shoot remote *if the remote carries
one*. RIVALS usually lets the server read the camera, in which case there is
nothing to rewrite and silent aim does nothing.

ESP: chams (`Highlight` in a hidden folder with `Adornee`, never a child of the
character), BillboardGui tags that follow the head via `Adornee`, screen-space
boxes, tracers, health / distance / weapon tags, a hard distance cut-off, a
250-item cap and a FOV ring. Movement: speed and jump under the safe-mode
ceiling, fly with an unbranded `BodyVelocity`, noclip, anti-void, anti-fling,
anti-ragdoll, anti-stun, fall-speed cap, low gravity. Utility: auto queue and
leave through the game's own buttons then the remotes, auto GG, anti-flash,
smoke removal, VFX / FPS pass, fullbright with restore, camera FOV, chat and
emote loops, server hop. Weapons: preset equip through the loadout button or
the equip remote, reload, and the Update 23 numbers on the page.

**The anti-cheat layer — what it does and what it cannot do.** RIVALS is not a
game that shrugs at scripts. Nosniy Games publish one line — *"Cheaters will be
permanently banned with no second chances"* — and community reports describe the
mechanism: an unexpected object under `LocalPlayer`, or impossible aim and fire
cadence, is flagged, and the ban lands in a wave days later rather than on the
spot. Roblox's Hyperion sits under all of it and is what actually catches
injectors.

Six layers, each of which reports whether it armed: local detector scripts whose
names say anti-cheat / monitor / integrity / enforcer are disabled; outgoing
report / flag / screenshot remotes are dropped at the `__namecall` level
(*outgoing calls only* — blocking `IsA` on a remote named `…Report…` would break
the game's own code, which this build found the hard way); `LocalPlayer:Kick` is
swallowed; `WalkSpeed` and `JumpPower` read as 16 / 50 to anything but the hub
itself (opt-in — `AcCamouflage` is off by default because the hook runs on every
instance property read and costs frames); numeric `maxspeed` / `speedlimit`
fields found in the Lua heap are clamped; and the hub's own traffic is paced — teleports move 12 studs at a time,
fire is capped, aim cannot snap more than 9° per frame, every remote has a token
bucket.

What it cannot do: hide an injected executor, undo a shot the server already
resolved, or make the account safe. **Alt-only mode is on by default** and
refuses the loudest toys (fly, noclip, rainbow, disco, music, chat spam, kill
effect, auto fire, auto melee) until you turn it off yourself. That default is
deliberate.

Harness: `tools/rivals_test.py` boots this exact file in a mocked Roblox — a
duel arena with a wall, two enemies and a teammate, a perspective camera, a
`Drawing` table, real `__namecall` dispatch, `hookmetamethod`, `getgc`, the
report remotes and four detector scripts — and drives it. 130/130 checks,
including the silent rewrite, the report drop, the kick guard, the camouflage,
the limiter clamp, the paced teleport, panic and unload, the camera swap in the
middle of a session, a full character respawn with aim re-engaging afterwards,
the hybrid mouse step and its automatic fallback, plus the hub's own 40-check
self-test.

### Steal An Egg — what is in this build (2026-10-17)

Nine tabs: **Steal · Base · Farm · Movement · ESP · Events · Anti-Cheat · Fun ·
Player & Misc**, 70 switches, one status panel per tab.

The loop: pick an egg by rarity × mutation × value against distance → travel to
its nest with bounded movement steps → fire the nest's own ProximityPrompt (or
ClickDetector, or the steal remote if the nest answers no prompt) → verify the
egg is really in your hands → carry it home → fire the plot's place prompt.
Guardians drop what you carry, so the hub drops the egg on purpose first and
goes back for it; other players' drops can be sniped.

Everything else on the base: auto hatch, index claims, offline earnings, trail
purchases, fuse, sell-below-rarity, auto equip best, treadmill training and its
upgrade prompt, rebirth.

**The anti-cheat layer — what it does and what it cannot do.** Steal An Egg has
no published ban API and no meaningful automated anti-cheat; what it does have
is a movement sampler that rubber-bands a client whose speed does not match the
account, and a server that decides whether an egg stays in your hands. Six
layers fight the client-side half:

1. detector scan + `Disabled = true` on the watcher scripts (and their
   `GetPropertyChangedSignal` connections dropped through `getconnections`);
2. a `__namecall` filter that drops report / flag / screenshot remotes —
   `newcclosure`-wrapped, receiver-checked, everything else falls through;
3. a kick guard on `LocalPlayer:Kick`;
4. WalkSpeed **read** camouflage through `hookmetamethod(game, "__index")`:
   the game's own scripts read a plausible number while the hub keeps the real
   one in `state.realSpeed`;
5. a speed-limit patcher that walks `getgc(true)` and clamps numeric limit
   fields;
6. paced movement: every travel is a series of ≤ `AcStepSize` hops (default 12
   studs, 50 ms apart) with a single-owner travel lock, plus a remote rate
   limiter and three pace profiles.

What none of this can do: out-argue the server. The server knows where you are
and whether the egg left the nest; nothing on the client changes that. The
build is not undetectable and does not claim to be. In the harness the filter
blocks the report remotes, the kick never reaches the client, the camouflaged
read returns 60 while the real speed is 220, and the limiter clamps 2 config
fields — all measured, see `tools/stealegg_test.py`.

**Known limits.** Remote and prompt names drift every week, so the hub resolves
them by name lists and falls back prompt → ClickDetector → remote → GUI button;
if a future update renames all four, auto steal stops and says so instead of
firing at random. `Walk` travel uses `Humanoid:MoveTo` and therefore follows the
game's own pathing; the three other modes write CFrames in bounded steps and
`Fly` needs a BodyVelocity-capable executor (all of them have it).

### Performance budget (Jujutsu Shenanigans, 2026-10-16)

The rebuild replaced the per-frame style of the first version with a two-tier
scanner (a full map walk every `ScanInterval` seconds, a cheap position refresh
every `RefreshInterval`), a write cache that only touches a property when its
value actually changes, pooled hit sparks, one-shot key/mouse releases instead
of a coroutine per press, and memos for the things that were re-read every
frame (character, root, humanoid, held tool, own aura, GUI buttons).

Measured by `tools/perf_test.py` and an A/B over the same mock, 22 virtual
seconds with every toggle on (`BEFORE` = the R23 build at `bb80236`):

| engine calls (22 virtual seconds) | before | after |
|---|---|---|
| `GetDescendants` | 4,884 | **477** |
| `IsA` | 9,067 | **630** |
| `FindFirstChild` | 3,108 | **564** |
| `FindFirstChildOfClass` | 3,650 | **494** |
| those four, together | 20,973 | **2,250** (9.3× less) |

Loop cost fell from 7.8 ms to 5.2 ms per virtual second in the mock (1.5×), and
`FindFirstChildWhichIsA` from 12.0/s to 3.9/s. `Instance.new` is a one-time
cost and did not change: the window builds ~5,000 instances when it opens, then
settles at ~5/s while running. The Anti-Cheat tab now carries a
**Performance** section — a live counter pill in the rail, the interval sliders
that are the actual budget, and a **Measure now** button that samples one second
of the hub's own counters and writes a report from them. Nothing in that panel
is guessed: the client cannot count Roblox's internal calls, so it reports what
it can see — walks, instances visited per walk, scan duration, writes, writes
skipped, values reused.

The Jujutsu Shenanigans build is written against the live game (v1.79 + Sky
Assassin + the 2026-10-13 patch): M1 melee, skills 1-4, Q dash, F block, R
special, G awaken, Black Flash (2.5×), burst, domains, roulette queue. Its
anti-cheat tab finds and disables client-side detector scripts, drops outgoing
report / flag / ban remotes at the namecall level, blocks a client kick, and
keeps the hub's own traffic in a plausible range. It does **not** and cannot
make a script undetectable — the server decides what the server believes.

## 1. Blox Fruits Hub — closed build (key system)

**One link for everybody, one key to enter:**

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/ameksi-web/Skill-Hub/arena/99225303-skill-hub/loader.lua"))()
-- opens the key window: type the key into the field, press Enter (or the ВОЙТИ button)
```

Current key: **`UPDATE 2026`** — replaced with every update (`tools/build_release.py --pass "<new key>"`).

The key window is part of the loader: a card with the title `Skill Hub · Введите ключ доступа`, one focused text field, a `ВОЙТИ` button and a status line (`Ключ нужен для запуска` / `Неверный ключ — попробуй ещё раз` / `Проверяю ключ…`). Nothing is downloaded or executed until a key is actually accepted; a wrong key only re-prints the status line. On success the key is written to `skillhub.key` in the executor workspace, the window disappears, and every later injection boots straight into the hub without asking again.

Power users can still skip the window entirely:

```lua
-- the key as an argument:
loadstring(game:HttpGet("https://raw.githubusercontent.com/ameksi-web/Skill-Hub/arena/99225303-skill-hub/loader.lua"))("UPDATE 2026")

-- or save it once, then a plain run never asks:
writefile("skillhub.key", "UPDATE 2026")
loadstring(game:HttpGet("https://raw.githubusercontent.com/ameksi-web/Skill-Hub/arena/99225303-skill-hub/loader.lua"))()
```

What the loader does after the key is accepted: downloads the locked blob → unlocks it → checks the plaintext really is a Skill Hub build → verifies the pinned FNV-1a-32 checksum (a modified blob is refused, not executed) → prints build + hash + key hash → unloads any previous instance → runs the hub.

**The readable source is private.** `main.lua` is not in this repository (GitHub returns 404 for it) — the published artefact is only the locked blob, and the sealed Lua inside it has its comments blanked and every string literal encrypted. Nobody who has the repository can read the script.

**Rotation is the revoke button** — publishing an update with a new key cuts off everybody who had the old one:

```bash
python3 tools/build_release.py --pass "UPDATE 2027"    # re-lock the build with the new key
git add -A release loader.lua && git commit -m "update + new key" && git push
```

**Release commands**

```bash
python3 tools/build_release.py            # re-lock the build, re-pin loader.lua, print stats
python3 tools/build_release.py --check    # verify the published blob still unlocks to the current source
python3 tools/build_release.py --selftest # python ⇄ Lua agreement on hash, unlock and lock
python3 tools/build_release.py --unseal   # local readable copy (git-ignored, never published)
```

* **Fruits & Raids** — stock sniper, **Fruit Magnet** (`firetouchinterest` + Handle pull), gacha roller with `OriginalName` auto-store behind a **first-sight acquisition ledger** (Update 30 moved the Gacha Dealer to Middletown), raids & awakening.
* **Teleport & Seas** — all-sea island tween teleport (S1/S2/S3 prefixed), sea travel, **Sea Detection control** (Auto / force 1-2-3 + live report).
* **ESP & Visuals** — Player ESP with PvP + full loadout, rarity-coloured Fruit ESP, chest/island/Mirage/Kitsune/boss ESP, tracers.
* **Misc & Settings** — **Undetected Bypass Fly**, Walk on Water, Infinite Geppo, Infinite Energy, No Dash Cooldown, Auto Collect Drops, Sea Event / Mirage tracker, Server Status HUD, anti-cheat disabler, rejoin/hop, FPS boost.

* **Hook engine is now opt-in (zero background interference)** — metamethod hooks cannot be removed from a live client, so the hub no longer installs one by default. Everything else (farm, PvP hunter, ESP, fly, anti-stun, anti-cheat watchdogs, SimRadius) is plain removable Lua. `Misc → Metamethod Hook Engine` turns the single safe hook on when you want the Kick guard, security-remote blocking and the aim raycast redirect; the status panel shows how many calls it intercepted (`CoreGui touched: never`).
* **Hook engine rewritten (fixes the CoreGui `attempt to call a nil value` error)** — the script used to install two raw, chained `__namecall` closures plus a raw `hookfunction(LocalPlayer.Kick)`, and it blocked any remote whose name merely *contained* generic words like `check`, `log`, `ban` or `flag`. That leaked into Roblox's own `CoreGui` modules. Now there is **one** unified hook: `newcclosure`-wrapped, `pcall`-protected with guaranteed fall-through to the untouched original call, blocking only unambiguous security endpoint names, with the Kick guard limited to `LocalPlayer`. A **Safe Hook Mode** toggle (default ON) disables interception entirely if an executor misbehaves, plus a live **Hook & Anti-Cheat Status** panel.
* **Animation load spam reduced** — `Bring Mobs` no longer destroys mobs' `Animator` (which made the engine keep replicating animation tracks for a dead animator). It can optionally stop the playing tracks instead.
* **`SimulationRadius` is now finite (`9e9`)** — `math.huge` produced `inf`/`NaN`, which corrupted physics, animation state and remote payloads downstream.

### Interface — "Porcelain" design system (2026)
* Soft-dark graphite surfaces in five intentional elevation steps, 1px hairline borders and 20px window radii — depth comes from surface layering and a soft drop shadow, **not** from neon or glow.

### v3.10 — GUARD: anti-theft, anti-tamper, request privacy

**The honest part first.** A script that runs on somebody else's client can always be dumped by that client — no client-side trick changes that. What *can* be done is make a stolen copy **useless**, **traceable** and **refused**. That is what this release does, in three layers: the hub's own guard, a protected loader, and a sealed release build.

**1. Guard inside `main.lua`** (Misc → *Guard · anti-theft & request privacy*, and `SharedEnv.SkillHubInstance.guard`):

* **Pristine references** — `game.HttpGet`, `game.HttpPost`, `loadstring`, `debug.info` are captured once as plain function values and always invoked as **plain functions**, so a `__namecall` / `__index` hook installed by another script (before or after us) never sees, rewrites or fakes our calls.
* **Fingerprint** — a HWID-derived 12-char tag (`hash32(hwid .. "|skill-hub")`), shown in the status panel, printed at boot, attached as `X-SkillHub-Tag` to every request we tag. A leaked copy names the machine it came from.
* **Licence gate** — `Config.LicenseKeys` (FNV-1a hashes). Empty list = no gate (default). With a list, `Guard Mode = enforce` stops the combat engines on a copy that was not authorised (`Guard.blocked()` gates `fireAttackPackets` and `attackCharacter`) instead of quietly working for a thief. Misc prints *your* key hash so you can authorise a key by pasting it in.
* **Tamper audit** — the identity of all 31 engine closures is recorded at boot (`debug.info(fn, "s")`) and re-checked every `Config.TamperAuditSeconds` (default 30 s). If another script swaps one out, the console says which one, and in `enforce` mode firing halts so a hijacked hub cannot get *you* banned.
* **Hook radar** — reports whether the game's metatable currently carries `__namecall` and whether it is a Luau closure (i.e. somebody else's hook) instead of guessing.
* **Export seal** — `getgenv().SkillHubInstance` is wrapped in a metatable (`__metatable`, `__newindex` error) so nothing outside can overwrite `unload`, `config` or our callbacks — the classic move of replacing a hub's functions through `getgenv()`.
* **No third-party code** — the old `PreferExternalFluent` code path that pulled `dawid-scripts/Fluent` from GitHub is **removed**: a foreign payload runs in the same environment as this hub and could hook it or read the user's requests. The Porcelain interface is ours, so nothing is fetched.
* **Sealed secrets** — `Config.SealedEndpoint` holds a webhook/API url **XOR-sealed with a keystream derived from the machine fingerprint** (`tools/seal_secret.py`). The file never contains the url; on any other machine the blob is noise and the hub prints *fingerprint mismatch* instead of using it. The hub itself stores **no** plaintext endpoint.

**2. `loader.lua` — the link you share**

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/ameksi-web/Skill-Hub/arena/99225303-skill-hub/loader.lua"))()
```

It captures `HttpGet` as a plain function, downloads the **sealed** build, verifies its FNV-1a-32 checksum against the value written by `tools/build_release.py` (a modified payload is **refused**, not executed), prints build + hash + machine tag, optionally enforces a key list (`RequireKey = true`, `Keys = { "<hash>" }`), unloads any previous instance, runs the payload and drops the payload reference again.

**3. `release/skillhub.release.lua` — the locked build**

`python3 tools/build_release.py` replaces every comment with spaces (**line numbers are preserved exactly**, so all `SkillHubStep("main.lua:1471", …)` labels keep their meaning), encrypts every string literal into `__S("<seed><hex>")` decoded at runtime by a 4-line XOR decoder on line 1, and writes the payload checksum into `loader.lua`. Verification for the last build: 2 179 literals sealed, 593 comments blanked, 7 704 → 7 704 lines, `LOAD OK` in the mocked-Roblox harness with zero tab errors, and no `rbxassetid` / `discord.com` / `game:HttpGet` plaintext left in the file.

**Commands**

```bash
python3 tools/build_release.py          # rebuild the locked payload + re-pin loader.lua
python3 tools/build_release.py --check  # verify the published blob still unlocks to the pinned checksum
python3 tools/seal_secret.py --selftest # prove python ⇄ Lua agree on the sealing
python3 tools/seal_secret.py --tag "<fingerprint from Misc>" --seal "https://discord.com/api/webhooks/…"
```

**The only way to make the source itself unreadable** is to stop publishing it: move `main.lua` to a private repository (or serve the sealed payload from a key-gated Cloudflare Worker) and distribute `loader.lua` alone. Until then the protection is: sealed build in the open, source of truth private-or-public by your choice, and a leaked copy that is traceable, checksum-refused and licence-stoppable.

### Critical fix (v3.7.2) — why the hub stopped loading, and what changed
**Root cause.** Lua (and Luau) allow only **200 active local variables per function**. `main.lua` is one giant chunk, and by commit `f776e6d` it had grown to **205** top-level locals, then 234 with the redesign and 259 with the diagnostics — so the file **no longer compiled at all**: the executor printed a compile error and the hub never started. Everything after that commit (design, hook work, console-error rounds) was shipping into a file that could not run.

**Fix.** The engine layer and the interface each run inside their own *factory function* now and hand their results back through a table:

```
               main chunk: ~130 locals   (was 259, limit 200)
local EngineFactory = function(E) … end   -- farm / PvP / ESP / fly / hooks
local UIFactory     = function(E) … end   -- "Porcelain" interface + all tabs
```

**Verification.** The file is now *executed* (not just parsed) in a harness with a mocked Roblox environment: it runs from the first line to the boot banner, connects 1 373 signals, and the evidence reporters print. Any further chunk-level local variable should go into one of the factories instead.

* **Escape hatches**: `SkillHubNoHooks`, `SkillHubNoVirtualInput`, `SkillHubNoEsp`, `SkillHubSafeMode`, `SkillHubMinimalMode` (UI only, everything else off).

### Diagnosing console errors
Roblox tags each console line with where it was raised:
* `[Roblox][CoreGui...] ... Script 'CoreGui.<id>'` → raised inside a script that lives in `CoreGui` (Roblox's own CoreScripts are the usual owner of the `RobloxGui.Modules.Common.Locales.en-us` message; injected code can also reach that formatter through unofficial engine APIs, which is why the hub stops calling them by default).
* `-- [Blox Fruits] ...` → raised by the game.
* Lines without those tags that mention `main`/your executor → raised by scripts you injected.

The hub now *measures* this instead of asserting it: the boot line `[Skill Hub] CoreGui audit @ injection: … numeric-named: …` and the watchdog report printed with every engine error show whether a CoreGui script existed before the hub ran and whether anything was added to CoreGui while it was alive. Load with `Misc → CoreGui Watchdog` on (default) and send that block whenever a red `CoreGui` line appears.

**v3.8 — the reporter can no longer stay silent on your line.** The LogService handler used to require the text `CoreGui`/`Locales` *inside* the message before it printed anything; executors frequently hand the line over without that prefix (the script name is formatted by Roblox, not carried in the payload). Now **any** `attempt to call a nil value` error is captured, our own `[Skill Hub]` output is ignored so the dump cannot feed itself, and the boot log prints

```
[Skill Hub] console watchlist armed · LogService.MessageOut + ScriptContext.Error · every "attempt to call a nil value" now prints our action trace, the CoreGui snapshot and the failing instance name
```

If that line is **not** in your console above the red text, the build that ran is not v3.8 (a cached copy of an older `main.lua` — GitHub raw caches for ~5 minutes; re-execute). If it *is* there and the red line still appears, the block underneath it is the answer and always contains the failing instance name, the CoreGui state before/after the hub started, the last tab switches/actions the hub performed, and which layers were active (`synthetic input`, `hookEngine`).

If you want to prove a console error does **not** come from this hub, load it with the hook engine completely off:

```lua
getgenv().SkillHubNoHooks = true
loadstring(game:HttpGet("https://raw.githubusercontent.com/ameksi-web/Skill-Hub/arena/99225303-skill-hub/main.lua"))()
```

Other safety nets: meteathod hooks **cannot be removed** from a running client, so re-executing an updated build cleanly unloads the previous instance first (double-injection guard); **Safe Hook Mode** makes the hook a pure pass-through; and **Misc → Unload Skill Hub** tears everything down.

## 2. Roblox Studio Plugin — Skill Animator Studio v2

A keyframe editor for Studio that writes **native animation data**: a
`KeyframeSequence` whose `Pose` tree is matched joint-by-joint to the rig's
`Motor6D`s (`Pose.Name` = `Part1`, parent `Pose` = `Part0`). It also reads such a
sequence back into the timeline, and stores a project on the rig itself.

**Full guide:** [`SkillAnimator/TUTORIAL.md`](SkillAnimator/TUTORIAL.md) — what a
plugin is, the three ways to install one, lifecycle/undo/cleanup rules, how the
`.rbxmx` is built, how the mocked-Studio test works, and 12 mistakes worth
avoiding.

Install the model file:

1. Studio → **Plugins** tab → *Plugins Folder* → drop `SkillAnimator.rbxmx` in
   (directly, not in a subfolder) → restart Studio.
2. Or, without a restart: Explorer → right-click `Workspace` → *Insert from File…*
   → pick `SkillAnimator.rbxmx` → right-click the inserted `SkillAnimator` script
   → **Save as Local Plugin…**.

Then: **Plugins → Skill Animator → Bind selected rig**.

What v2 does:

| | |
|---|---|
| Export | one `Keyframe` per frame, `Time = frame / FPS`, `Pose` per joint, correct `Part0 → Part1` nesting, per-key easing, `Loop`/`Priority` |
| Import | an existing `KeyframeSequence` from `AnimSaves` back into the timeline |
| Project | Save/Load on the rig (attribute `SkillAnimatorProject`), survives a Studio restart |
| Timeline | zoom 1×/2×/4×/8×, auto-stepped ruler, scrub, diamonds, ◀ ▶ key navigation, duplicate, delete |
| Inspector | RX/RY/RZ ±180°, PX/PY/PZ ±4, FPS, length, animation name, reset joint |
| Safety | one undo waypoint per action (drag/slider batched), everything torn down on close and on `plugin.Unloading` |

Verify it without Studio (mocked Studio, real 3×3 CFrame maths, R6 rig, 47 checks):

```
/tmp/venv/bin/python tools/animator_test.py    # → 47/47, PLUGIN OK
python3 tools/build_plugin_rbxmx.py            # rebuild the .rbxmx, self-verified
```

Honest limits: `Motor6D` only (no `Bone`/IK rigs), part names must be unique,
no onion skin or multi-rig editing, and the project attribute is text — very large
animations should be kept as `AnimSaves` exports.
